How I build

How an app gets made

Every app goes through the same steps. Agents do the work at each step. I choose the idea and review the result before it moves on.

  1. Idea analysisCompetitors, monetization model and a content plan.
  2. ContentParallel subagents write puzzles, word packs or cards in bulk.
  3. The appSwiftUI, MVP with dependency injection, unit tests, StoreKit 2.
  4. LocalizationOne agent per language, up to 28 languages. Another agent then checks that each translation sounds natural.
  5. Store assetsScreenshots, legal pages and App Store metadata with keywords per market.
  6. Submission and reviewApp Store Connect setup, in-app purchases, submission and replies to App Review.
Skills

My Claude Code skills

A skill is a set of instructions that lets Claude Code do a whole task on its own. I use these every day.

ios-app-factory

Takes an app idea, a similar app or an App Store link and turns it into a finished iOS app. It checks the niche, plans the content, writes it with several agents at once, builds the SwiftUI project with tests, and prepares screenshots, legal pages and App Store Connect.

ios-app-update

Makes the next version of an app that is already in the App Store. It plans the release from the project's docs, builds and tests it, updates screenshots and the store page, then uploads and submits the build.

ios-app-localize

Translates an app into 28 languages. Each language gets its own agent. Then another agent rereads every translation, and the app is checked in each language.

appstore-review-fix

Deals with App Review rejections. It reads Apple's message, checks the code, fixes the problem, writes a short reply and sends the app back for review.

tauri-design-new / review

Designs the interface of a Tauri desktop or mobile app from scratch, or reviews an existing one against Apple, Microsoft and Google guidelines.

web-design-new / review

Does the same for web apps and admin panels. It makes a clickable prototype for a new app, or a list of fixes for an existing one.

nuget-update

Publishes a .NET package to NuGet after code review. It builds from a clean checkout, checks the version and uploads the package.

How I work

Rules I follow

  • Plan firstThe agent writes a plan before any code. I read it and change it if needed.
  • Notes in the repoEach project has a CLAUDE.md file, release notes for every version and handover notes. A new session reads them and knows where things stand.
  • Separate copies for agentsWhen several agents change code at once, each works in its own git worktree with its own simulator.
  • Test on a real iPhoneSome crashes never show up in the simulator. Before I submit a release, I go through a checklist on my phone.
  • Write down every mistakeWhen something goes wrong, I write down what happened, why, and what to do so it doesn't happen again.
  • Plain languageAll app and store text gets a separate review so it reads simply and naturally, in every language.
